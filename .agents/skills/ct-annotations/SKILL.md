# Codetool annotations

Run `provider-update` for explicit update requests, applicable annotations,
subscribed resource-change hints and other confirmed current-source changes.
Select the own [update skill](../ct-update/SKILL.md) for the same complete process:
read current context through the native binding, reconcile the complete applicable
package and dependency declaration, implement locally, run actual checks, update
own canonical annotations and verify callable output, then fulfill onward duties
and applicable reorganisation. Resolve unknown outcomes before retrying and
reconnect after invalidation. Each next receiver, including terminals, MUST
implement its own selectable update skill and pass `provider-update` and this
complete process through its own contract, function, annotations, update and
delivery skills and work instructions to every further stage. A hint selects
work; it grants no foreign-project, publication or automatic Doctor authority.

Codetool's function skills describe the complete supported functions. This
skill is the single source of currently necessary change notices. Discover the
`annotations` MCP function through the stable `bin/provider mcp` entry and call it
with the current schema, optionally filtering by function. It projects the block
below with provider ID only. An empty relevant list requires no
notice-specific action but never waives the announced-change duty. Remove a
notice when unnecessary; keep no reader ledger,
acknowledgement, announcement history or consumer queue.

`annotations` requires no function-specific argument. Optional `function` filters
the current notices by the declared function name; use its current MCP schema.

Optional MCP `use_case` carries the literal task selection into the existing
source-review due inquiry. Omission keeps catalog default `library`, without
remembered context. Pure `bin/provider annotations` performs no due inquiry and
gains no flag. Carry matching task context through current schemas/native owners
onward; create no saved choice, Root selector, extra review/store or new completion
time to silence a wrong-context inquiry.

Select the own [Doctor skill](../ct-doctor/SKILL.md) only for diagnosis explicitly
requested by the user in the authorized project. Phases never start or repeat it
automatically. It maps meaningful CT observations and existing check owners to
common findings/coverage, keeping unexecuted work visible. Discover callable
availability: PP supplies declared bounded read-only inspection/plausibility;

this describes CT's implemented scope, not a PP restriction on productive local
diagnostics. Suitable declared procedures may have contained runtime effects,
